# 언제 만날래 — 모바일 React 프로토타입

친구들의 가능한 날짜·점심/저녁을 모으고, 지역을 투표한 뒤 음식점·카페 링크를 저장하는 모바일 웹입니다. 계정과 방은 서버의 Cloudflare D1에 저장됩니다.

## 실행

Node.js 22.13 이상이 설치된 환경:

```sh
npm install
npm run dev
```

기본 주소: http://localhost:3000

이 PC에서는 `start-local.ps1`로도 실행할 수 있습니다. 실행 중인 서버가 있으면 기존 주소를 사용하세요.

## 체험 순서

1. 닉네임과 숫자 4자리 PIN으로 입장합니다. 처음 쓰는 닉네임은 계정이 생성됩니다.
2. 모임 이름, 고정 정원(2~10명), 7~31일의 기간을 정합니다.
3. 친구 초대에서 링크를 복사해 전달합니다. 친구는 자신의 기기에서 로그인 후 참가합니다.
4. 각자 달력의 점심·저녁을 선택해 제출합니다. 설정 인원 전원 제출 시 마감됩니다.
5. 방장이 날짜·시간대를 확정하고 참석자들이 지역에 투표합니다.
6. 동률이면 방장이 재투표 또는 무작위 선정을 선택합니다.
7. 최종 화면에서 음식점·카페 링크를 함께 모읍니다.

화면은 4초마다 서버 상태를 확인합니다. 같은 계정으로 다른 기기에 로그인하면 기존 모임과 제출 기록을 볼 수 있습니다. 이전 localStorage 체험 계정과 샘플 방은 서버로 이관하지 않습니다.

## 구현 범위

- React 19 + TypeScript, Vite/Vinext 기반 로컬 프로젝트
- 기본 너비 430px, 360px 모바일 대응, 하단 고정 버튼·네이티브 dialog 바텀시트
- 계정·여러 모임·고정 정원·기간 검증·달력 제출·날짜 후보·참석 재확인
- 지역 추가 마감·투표·동률 재투표·추첨·최종 링크 보드
- 방장 위임·강퇴·나가기·종료·만료 조회 제한
- D1 영구 저장, HttpOnly 세션 쿠키, 초대 링크와 코드 입장, 4초 간격 동기화
- 서버 권한 검사, PIN 솔트/PBKDF2 해시, 로그인 시도 제한, 동시 변경 충돌 재시도

## 실제 서비스와의 차이

이메일 발송과 네이버 정보 자동 완성은 미구현입니다. 이메일 입력창도 숨겼습니다. PIN 복구는 지원하지 않습니다. 4자리 PIN은 사용자 요청에 따른 간편 인증이며, 높은 보안 수준을 요구하는 개인정보를 저장하는 용도로 설계하지 않았습니다.

날짜는 한국 시간 기준입니다. 약속일 다다음날 00:00부터 접근할 수 없으며 이후 첫 API 요청에서 만료된 방을 삭제합니다. 무접속 상태에서 정확히 00:00에 물리 삭제하는 예약 작업은 아직 없습니다. 개발 DB는 `.wrangler` 아래 로컬 저장소로, 배포 DB와 분리됩니다. `drizzle/0000_shared_rooms.sql`은 배포용 초기 스키마이며 로컬 API도 동일 테이블을 준비합니다.

현재 미정 정책의 체험 가정:
- 집계 이후 방장이 최종 날짜·시간대를 확인합니다.
- 후보 외 날짜 참석 재확인은 현재 활성 멤버 전원 기준입니다.
- 방장은 넘기기 또는 종료 후 나갈 수 있습니다.
- 지역 확정 뒤 날짜/지역 변경 UI는 제공하지 않습니다.
- 링크 이름은 직접 입력합니다. 자동 미리보기는 연결 전입니다.

## 코드 위치

- `app/page.tsx`: 화면·서버 동기화 및 인터랙션
- `app/api/meeting/route.ts`: 인증·세션·D1 저장·동시 업데이트 처리
- `lib/room-actions.ts`: 서버에서 실행하는 권한 및 투표 상태 전환
- `app/globals.css`: 디자인 토큰과 모바일 스타일
- `lib/meeting.ts`: 데이터 모델·날짜/지역 집계
- `app/layout.tsx`: 한국어 문서·메타데이터

## 검증

```sh
npx tsc --noEmit
npm run lint
npm run build
```

별도 세션의 HTTP API 검증으로 동시 투표 보존, 타 계정 방 격리, 방장 권한, 지난 회차 투표 거절, 재접속, 링크 공유, 나가기와 로그아웃을 확인했습니다. 실제 브라우저 조작·시각 검증은 별도 수행하지 않았습니다.
